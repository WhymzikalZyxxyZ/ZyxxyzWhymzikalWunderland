Architecture

The status page is powered by a Cloudflare Worker with a cron trigger that probes each service every 5 minutes. Results are stored in a Durable Object (SQLite) and served via a public JSON API. The static page polls the API every 60 seconds — no backend required at read time beyond the edge Worker.
Cron trigger (*/5 * * * *) │ ├─ HEAD https://zyxwonderland.xyz → ok / latency_ms └─ HEAD https://mail.zyxwonderland.xyz → ok / latency_ms │ ▼ StatusDO (Durable Object — SQLite) ├─ Table: checks(service_id, ok, latency_ms, ts) ├─ Retention: 90 days │ ├─ GET /api/status → latest check per service + 90-day uptime % └─ GET /api/sparkline?svc=X&n=90 → last 90 results as bool array │ ▼ status.html (static page, polls every 60s) ├─ Service cards with operational / outage badge └─ Canvas sparkline — each bar = one check (green/red)
The Durable Object is keyed by the string "singleton" so all writes and reads go to the same instance, guaranteeing consistent time-series data without coordination. Old records are pruned on every write to keep storage bounded. The sparkline pulls the most recent 90 checks (~7.5 hours at 5-minute intervals) and renders them as a bar chart directly on a <canvas> element — no third-party charting library.
